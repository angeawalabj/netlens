# Jour 20 — Monitoring réseau et observabilité

## La situation réelle

À 2h du matin, vos alertes se déclenchent. La latence de votre API a doublé. Vous avez 5 minutes pour diagnostiquer si c'est un problème réseau, applicatif, ou infrastructure. Qu'est-ce que vous regardez en premier ?

---

## Les 4 signaux dorés (Google SRE)

1. **Latency** : temps de réponse (p50, p95, p99)
2. **Traffic** : requêtes par seconde
3. **Errors** : taux d'erreurs (5xx, timeouts)
4. **Saturation** : utilisation des ressources (CPU, RAM, bande passante, connexions)

---

## Métriques réseau essentielles

```bash
# Bande passante en temps réel
iftop -i eth0          # par connexion
nload eth0             # global
nethogs                # par processus

# Statistiques d'interface
ip -s link show eth0
# RX bytes, TX bytes, dropped, errors

# Connexions TCP
ss -s                  # résumé
ss -tan | awk '{print $1}' | sort | uniq -c

# Latence vers les voisins
ping -c 100 gateway | tail -1
# min/avg/max/mdev = 1.2/1.8/3.4/0.4 ms

# Perte de paquets
mtr --report --report-cycles 100 8.8.8.8
```

## Prometheus + Grafana

Stack de monitoring standard en production.

```yaml
# prometheus.yml — scraper les métriques
scrape_configs:
  - job_name: 'node'
    static_configs:
      - targets: ['localhost:9100']  # node_exporter

  - job_name: 'nginx'
    static_configs:
      - targets: ['localhost:9113']  # nginx-prometheus-exporter
```

**Métriques réseau node_exporter :**
```
node_network_receive_bytes_total{device="eth0"}
node_network_transmit_bytes_total{device="eth0"}
node_network_receive_drop_total{device="eth0"}
node_netstat_Tcp_RetransSegs   # retransmissions TCP
```

**Requête PromQL pour la bande passante :**
```
rate(node_network_receive_bytes_total{device="eth0"}[5m]) * 8
# → bits par seconde, moyenne sur 5 minutes
```

## Alertes réseau utiles

```yaml
# alertmanager rules
- alert: HighNetworkErrorRate
  expr: rate(node_network_receive_errs_total[5m]) > 10
  for: 2m
  labels:
    severity: warning
  annotations:
    summary: "Taux d'erreurs réseau élevé sur {{ $labels.device }}"

- alert: TCPRetransmissionHigh
  expr: rate(node_netstat_Tcp_RetransSegs[5m]) > 100
  for: 5m
  annotations:
    summary: "Retransmissions TCP élevées — congestion possible"

- alert: NetworkSaturation
  expr: |
    rate(node_network_transmit_bytes_total[5m]) > 0.9 * 1e9
  annotations:
    summary: "Interface réseau à >90% de saturation (1 Gbps)"
```

## Logs réseau structurés

```nginx
# nginx — format JSON pour parsing facile
log_format json_combined escape=json
  '{"time":"$time_iso8601",'
  '"remote_addr":"$remote_addr",'
  '"method":"$request_method",'
  '"uri":"$request_uri",'
  '"status":$status,'
  '"bytes_sent":$bytes_sent,'
  '"request_time":$request_time,'
  '"upstream_response_time":"$upstream_response_time",'
  '"http_referer":"$http_referer",'
  '"http_user_agent":"$http_user_agent"}';
```

**Analyser les logs avec jq :**
```bash
cat /var/log/nginx/access.log | jq -r \
  'select(.status >= 500) | "\(.time) \(.status) \(.uri)"' | head -20

# P95 de latence
cat /var/log/nginx/access.log | jq '.request_time' | \
  sort -n | awk 'BEGIN{c=0} {a[c++]=$1} END{print a[int(c*0.95)]}'
```

## À retenir

- 4 signaux dorés : latence, trafic, erreurs, saturation
- `ss`, `iftop`, `nethogs` pour diagnostics en temps réel
- Prometheus + Grafana = standard production
- Alerter sur les retransmissions TCP (congestion) et les erreurs d'interface
- Logs JSON structurés = analysables programmatiquement
- p95/p99 > moyenne pour la latence (la moyenne cache les problèmes)
