# Jour 18 — Sécurité réseau : firewalls, VPN et DMZ

## La situation réelle

Vous ouvrez un service web au public. Comment protéger votre infrastructure des attaques tout en laissant passer le trafic légitime ?

---

## Firewalls — filtrer le trafic

Un firewall applique des règles sur le trafic réseau. Trois types principaux :

**Stateless (filtrage de paquets) :** examine chaque paquet indépendamment (IP src/dst, port, protocole). Rapide mais limité.

**Stateful :** suit l'état des connexions TCP. Une réponse à une requête initiée de l'intérieur est automatiquement autorisée.

**Application-layer (WAF) :** inspecte le contenu HTTP. Bloque les injections SQL, XSS, etc.

### iptables / nftables (Linux)

```bash
# Voir les règles actuelles
sudo iptables -L -n -v
sudo nftables list ruleset

# Autoriser SSH entrant
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Autoriser HTTPS
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Bloquer tout le reste (DROP)
sudo iptables -P INPUT DROP

# Autoriser les connexions établies (stateful)
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Sauvegarder
sudo iptables-save > /etc/iptables/rules.v4
```

### ufw (Ubuntu — interface simplifiée)

```bash
sudo ufw enable
sudo ufw allow ssh
sudo ufw allow 443/tcp
sudo ufw deny 23/tcp     # bloquer Telnet
sudo ufw status verbose
```

## DMZ — zone démilitarisée

Architecture en 3 zones :

```
Internet
   │
[Firewall externe]
   │
[DMZ] ← serveurs web, reverse proxy, bastion
   │
[Firewall interne]
   │
[LAN interne] ← BDD, services internes
```

Les serveurs en DMZ peuvent recevoir des connexions d'Internet mais ne peuvent pas initier de connexions vers le LAN interne. Une compromission de la DMZ ne donne pas accès aux données internes.

---

## VPN — Virtual Private Network

Un VPN chiffre et encapsule le trafic dans un tunnel vers un point d'entrée distant.

**WireGuard (recommandé)** :

```bash
# Installer
sudo apt install wireguard

# Générer les clés
wg genkey | tee /etc/wireguard/private.key | wg pubkey > /etc/wireguard/public.key

# /etc/wireguard/wg0.conf (serveur)
[Interface]
PrivateKey = <clé_privée_serveur>
Address = 10.0.0.1/24
ListenPort = 51820

[Peer]
PublicKey = <clé_publique_client>
AllowedIPs = 10.0.0.2/32

# Démarrer
sudo wg-quick up wg0
```

**OpenVPN** : plus répandu, plus complexe, port UDP 1194 ou TCP 443.

---

## À retenir

- Firewall stateful = suit l'état des connexions (réponses autorisées automatiquement)
- DMZ = zone intermédiaire entre Internet et le LAN interne
- WireGuard = VPN moderne, rapide, configuration simple
- WAF = protection couche applicative (HTTP)
- Principe du moindre privilège : n'ouvrir que ce qui est nécessaire
